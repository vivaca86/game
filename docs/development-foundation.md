# 개발 기반 체크리스트

최종 기준은 밝은 파스텔풍, 귀여운 마스코트형 몬스터, 한글 전용 UI, 데이터 분리형 카드 던전 게임이다.

## 개발 환경

- 로컬 실행: `node tools/serve-static.mjs`
- 정적 빌드: `node tools/build-static.mjs`
- 카드 데이터 재생성: `node tools/generate-full-card-data.mjs`
- 카드 이후 콘텐츠 재생성: `node tools/generate-full-content-data.mjs`
- 데이터 검증: `node tools/validate-data.mjs`
- 런타임 스모크: `node tools/runtime-smoke-test.mjs`
- `npm`이 설치된 환경에서는 `npm run dev`, `npm run build`, `npm run data:validate`도 사용할 수 있다.
- 현재 구조는 별도 번들러 없이 브라우저에서 바로 실행되는 정적 HTML 기준이다.

## 첫 작업 순서

1. 개발 환경 고정
2. 한글 데이터 구조 고정
3. 카드, 보석, 몬스터, 스테이지의 최소 샘플 데이터 투입
4. 데이터 검증 도구로 누락과 참조 오류 확인
5. 전투 코어가 새 데이터 구조를 읽도록 연결
6. 보상, 보석, 유물, 스테이지 진행을 순서대로 연결

## 데이터 원칙

- 게임에 보이는 모든 문구는 한글 데이터에서 관리한다.
- 카드명, 몬스터명, 스테이지명, 보상명, 버튼명, 도움말은 코드에 직접 박지 않는다.
- 시스템은 원형 장르의 흐름을 참고하되, 이름, 세계관, 몬스터, 카드 모양, 카드 일러스트, UI 톤은 독자 IP로 유지한다.
- 데이터는 먼저 작은 샘플로 검증하고, 같은 구조로 전체 규모까지 확장한다.

## 목표 콘텐츠 규모

- 카드: 113장
- 보석: 50종 이상
- 캐릭터: 20명 이상
- 스테이지: 15개 이상
- 유물: 16종 이상
- 기운: 12종 이상
- 이벤트: 10종 이상
- 업적: 160개 이상

## 런타임 연결 현황

- 데이터 로더와 ID 인덱스 연결 완료
- 캐릭터/스테이지 선택 후 데이터 기반 탐험 시작 가능
- 손패, 덱, 버림더미, 기운, 비용, 카드 사용 연결 완료
- 카드 효과 op의 기본 처리기 연결 완료
- 일반전, 정예, 이벤트, 보상, 보스 방 진행 연결 완료
- 카드, 보석, 유물, 별사탕 보상 선택과 다시 보기 연결 완료
- 업적 트리거와 보상 연결의 첫 런타임 경로 완료
- 보석 보관함, 보석 인스턴스, 카드별 소켓 장착 구조 완료
- 보석 효과가 카드 비용, 피해, 보호막, 표식, 메아리, 확산, 연쇄 유지에 반영된다.
- 런 상태 저장 스냅샷에 덱, 손패, 버림더미, 보석 보관함, 장착 소켓, 해금, 유물, 업적, 스테이지 진행이 포함된다.
- 유물 16종은 전투 시작, 전투 종료, 보상 개수, 별사탕, 상점/이벤트 비용, 연쇄 보조에 연결된다.
- 기운 12종은 시작 기운 지급, 카드 사용 후 조건부 피해/회복/별사탕/드로우/비용 감소, 보석 보상 확률에 연결된다.
- 현재 빌드 UI에서 보유 유물과 기운을 확인하고 저장/불러오기 후 복원한다.
- 장기 진행 프로필에 스테이지 클리어, 업적, 카드/보석/유물/기운/캐릭터 해금, 마을 보상을 저장한다.
- 새 탐험은 프로필의 캐릭터/스테이지 해금 상태와 보상 풀을 기준으로 시작한다.
- 클리어/실패 결과 화면에서 이번 탐험 통계와 신규 해금 내역을 확인한다.
- 적은 스테이지 순서와 방 종류에 따라 체력, 방어, 의도 수치가 보정되고 역할명이 붙는다.
- 특수 의도는 표식, 약화, 기운 감소, 방해 카드, 관통 피해, 전체 방어, 회복, 연쇄 감소, 호출을 처리한다.
- 보스는 체력 페이즈 규칙으로 친구 호출과 장벽 보정을 발동하며 결과 화면에 보스 변화 횟수를 기록한다.
- `src/core/balance.js`에서 보상 골드, 상점 비용, 스테이지 클리어 골드, 적 성장 보정값을 1차 관리한다.
- 캐릭터 패시브와 마을 성장 효과가 전투 시작, 카드 사용, 피격, 정예 보상, 보석 보상 확률에 반영된다.
- 밸런스 자동 점검은 `node tools/balance-simulation.mjs --runs=12 --stages=1,3,6,10,15`로 실행한다.
- 그래픽 제작 기준은 `docs/art-direction.md`에 따로 두고 카드, 몬스터, 보석, 유물, 기운 에셋을 같은 기준으로 검수한다.
- 보석 작업대는 카드 타입 필터, 미장착 보석 카드, 소켓 미니 프레임, 장착 효과 요약, 장착 후보 미리보기를 표시한다.
- 상점, 이벤트, 전투 보상 화면은 별사탕/체력 비용, 구매 가능 여부, 부족 사유, 보상 미리보기 카드를 함께 표시한다.
- 보상 화면 브라우저 스모크는 데스크톱/모바일 스크린샷을 남기고 선택지 넘침과 모바일 1열 배치를 확인한다.
- 스테이지 목록은 각 스테이지의 방 타입 구성을 작은 칩으로 표시하고, 탐험 중에는 현재/다음/완료/보스 방을 경로판으로 보여준다.
- 스테이지 경로판 브라우저 스모크는 현재 방, 보스 노드, 방 개수, 데스크톱/모바일 반응형 배치를 확인한다.
- 전투 화면은 이번 턴 예상 피해, 보호막 차단량, 관통 피해, 플레이어 상태, 몬스터별 현재 의도와 다음 의도 타임라인을 표시한다.
- 전투 UI 브라우저 스모크는 몬스터 초상, 의도 카드, 의도 타임라인, 전투 예고판, 텍스트 넘침 여부를 확인한다.
- 지속 카드의 전투 규칙은 전투마다 초기화되며, 같은 색 카드 사용 시 보호막을 실제로 지급하고 전투 예고판에 활성 규칙을 표시한다.
- 반사 카드는 이번 턴 받은 피해를 기준으로 앞 적에게 피해를 되돌리고, 턴 종료 후 반사 상태를 초기화한다.
- 적 표식은 스택 수에 따라 다음 피해 보너스가 커지고, 피해를 받은 카드 처리 뒤 표식 1을 소모한다.
- 런타임 스모크는 표식 누적, 표식 피해 보너스, 표식 소모까지 검증한다.
- 방해/저주 카드는 전투 중 별도 정리 액션으로 사라진 카드 더미에 보낼 수 있으며, 임시 방해는 기운 1, 저주는 기운 2를 쓴다.
- 방해 정리는 카드 효과와 연쇄를 발동하지 않고, 전투 예고판에는 손패 방해 수와 이번 전투 정리 횟수를 표시한다.
- 브라우저 스모크는 임시 방해 카드를 주입해 방해 대응 패널, 점선 방해 카드 프레임, 정리 후 상태 칩, 전투 UI 넘침 여부를 검증한다.
- 후반 적 성장 완화는 8스테이지부터 낮은 폭으로 적용해 10스테이지 이후가 과하게 쉬워지지 않게 관리한다.
- 몬스터 초상은 텍스트 배지 대신 CSS 기반 얼굴, 귀, 볼, 계열 색, 정예 반짝이, 보스 왕관으로 표시한다.
- 보스 카드는 체력 기준 페이즈 변화, 발동 임박/완료 상태, 추가 장벽 수치를 별도 패널로 보여준다.
- 브라우저 스모크는 일반 몬스터 초상 구성과 보스 페이즈 패널, 보스 초상, 보스 패턴 UI 넘침 여부를 검증한다.
- 카드 일러스트 데이터의 subject/mood는 샘플 카드, 손패, 보상 미리보기, 보석 작업대의 공통 카드 아트 창에 연결한다.
- 카드 아트 창은 카드 타입과 일러스트 키워드에 따라 폭발, 방패, 별, 리본, 부적, 물약, 구름, 약속, 방해 모티프를 사용한다.
- 브라우저 스모크는 카드 샘플, 손패, 보석 작업대, 보상 미리보기의 카드 아트 표시와 넘침 여부를 검증한다.
- 보석 아이콘은 효과 색, 희귀도 테두리, 장착 가능 소켓 형태를 함께 표시한다.
- 유물/기운은 현재 빌드와 보상 미리보기에서 전용 아이콘, 희귀도 링, 짧은 효과 요약을 함께 보여준다.
- 브라우저 스모크는 보석 희귀도 아이콘, 유물/기운 빌드 아이콘, 유물/기운 보상 아이콘의 표시와 저장 복원을 검증한다.
- 탐험 시작 화면은 선택한 캐릭터의 초상, 역할, 패시브, 체력/기운, 시작 덱을 미리 보여준다.
- 탐험 시작 화면은 선택한 스테이지의 키아트, 바이옴, 보스, 방 구성, 클리어 보상을 미리 보여준다.
- 브라우저 스모크는 캐릭터/스테이지 선택 미리보기, 캐릭터 변경 시 갱신, 초상/키아트 넘침 여부를 검증한다.
