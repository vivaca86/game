# 프로젝트 복구 감사

작성일: 2026-05-23

## 결론

현재 프로젝트는 "풀 규모 완성"이 아니다. 기술적으로는 카드/보석/스테이지/전투/보상 흐름을 테스트할 수 있는 기반이 있지만, 최종 게임으로 믿을 수 있는 콘텐츠와 그래픽은 아직 없다.

지금부터는 기능 확장과 콘텐츠 대량 생산을 중단한다. 검증 가능한 작은 품질 샘플이 통과하기 전까지 카드 113장, 보석 58종, 업적 161개 같은 수량을 완성도로 부르지 않는다.

## 1. 추가 개발 중단

- 새 카드, 새 몬스터, 새 스테이지, 새 UI 기능을 더 쌓지 않는다.
- 현재 데이터 수량을 "완료"라고 말하지 않는다.
- CSS/DOM으로 만든 임시 그림을 실제 그래픽으로 취급하지 않는다.
- `npm run check` 통과는 기술 검증일 뿐, 콘텐츠 품질 검증이 아니다.
- 다음 개발은 품질 기준 샘플 승인 이후에만 진행한다.

## 2. 현재 산출물 손실 정리

### 유지 가능한 것

- 정적 웹 앱 기반과 실행 구조
- 한국어 데이터 파일 분리 구조
- 카드, 보석, 유물, 기운, 캐릭터, 적, 스테이지, 이벤트, 업적의 기본 스키마
- 전투, 보상, 진행, 해금, 저장 흐름의 개발용 골격
- 데이터 참조 오류를 잡는 기존 검증 스크립트들

### 최종품으로 믿으면 안 되는 것

- 카드 113장: 효과 구조와 네이밍이 템플릿 반복이다.
- 보석 58종: 효과 구조가 반복되어 개별 정체성이 약하다.
- 적 60종: 몬스터별 전투 의도와 개성이 충분히 설계되지 않았다.
- 스테이지 15개: 방 구성 패턴이 반복되어 스테이지 고유 경험이 약하다.
- 이벤트 10종: 3선택 구조는 있으나 서사/위험/보상 차별화가 부족하다.
- 업적 161개: 의미 있는 업적이라기보다 마일스톤 대량 생성에 가깝다.
- 그래픽 전체: 카드, 몬스터, 스테이지, 이벤트, 아이콘이 실제 에셋이 아니라 CSS/DOM 임시 표현이다.

### 폐기하거나 재기획해야 하는 것

- "풀 콘텐츠 완료"라는 기존 판단
- 대량 생성된 콘텐츠를 그대로 최종 데이터로 쓰는 계획
- CSS 도형 기반 카드 일러스트/몬스터 초상/스테이지 키아트
- 숫자와 연결성만으로 완성도를 판단하는 검증 방식

## 3. 작은 검증물 없이는 진행 금지

다음 세 가지가 먼저 통과해야 한다.

1. 카드 1장
   - 이름, 효과, 희귀도, 비용, 설명, 카드 프레임, 일러스트 방향이 실제 게임 투입 기준이어야 한다.
   - 템플릿 반복 카드가 아니라 고유한 플레이 이유가 있어야 한다.

2. 몬스터 1종
   - 외형 콘셉트, 전투 패턴, 의도 표시, 피격/행동 피드백 기준이 보여야 한다.
   - 같은 수치만 바꾼 몬스터가 아니어야 한다.

3. 전투 화면 1개
   - 밝은 유튜브 참고 풍의 실제 그래픽 방향이 보여야 한다.
   - 카드, 몬스터, 배경, 버튼, 결과 피드백이 한 화면에서 어울려야 한다.
   - 모바일/데스크톱에서 텍스트 겹침이 없어야 한다.

이 세 가지가 승인되기 전까지는 대량 확장, 완료 선언, 신규 시스템 추가를 하지 않는다.

## 자동 품질 감사

새 스크립트:

- `npm run quality:audit`: 현재 데이터/그래픽이 품질 게이트를 통과하지 못하면 실패한다.
- `npm run quality:audit:report`: 실패시키지 않고 보고서만 출력한다.

이 감사는 기존 `npm run check`와 목적이 다르다. `check`는 "참조가 깨졌는지/실행되는지"를 본다. `quality:audit`는 "대량 템플릿과 임시 그래픽을 완성품으로 착각하고 있는지"를 본다.

현재 상태에서는 `quality:audit`가 실패하는 것이 맞다. 실패가 곧 보호 장치다.
