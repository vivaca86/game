# 세로 조각 통과 기준 v1

작성일: 2026-05-26

## 상태

- 상태: 기준 초안
- 기준 문서: `docs/development-foundation.md`
- 기준 엔진: `Phaser 3 + TypeScript + Vite`
- 기준 그래픽풍: `프리미엄 팝업북 판타지 카드 크롤러`
- 목적: 본격 구현 전 첫 플레이 가능한 조각의 통과 기준을 고정한다.
- 아직 아님: 구현 완료, 브라우저 검증 완료, 원작 95% 유사도 판정

## 목표

세로 조각은 데모 전체가 아니라 최종 게임 구조의 축소판이다. 아래 흐름이 한 번 닫혀야 한다.

```text
마을 -> 월드맵 -> 던전 진입 -> 방 이동 -> 카드 전투 -> 보상 선택 -> 룬/보석 장착 -> 보스전 -> 해금 -> 마을 복귀
```

이 흐름이 닫히지 않으면 카드, 몬스터, 스테이지 수량을 늘리지 않는다.

## 포함 범위

- PC 웹 브라우저 기준 실행
- Phaser 씬 기반 전투와 던전 시야
- TypeScript 데이터 로딩
- 한글 표시 문구
- 손패 5장 전투 판단
- 몬스터 1종 이상
- 보스 1종 이상
- 카드 보상 1회
- 룬/보석 장착 1회
- 해금 또는 마을 복귀 상태 변화 1회
- 디버그 진입 도구
- 최소 저장 상태

## 제외 범위

- 전체 카드 수량
- 전체 스테이지 수량
- 전체 캐릭터 수량
- 전체 원작 대응 완료
- 온라인 계정, 클라우드 세이브, 랭킹
- 모바일 최적화 완료
- 최종 사운드와 음악
- 상점, 모든 이벤트, 모든 파워업의 완성

## 필수 화면

| 화면 | 통과 기준 |
| --- | --- |
| 마을 | 던전 진입 전 상태, 해금 상태, 시작 버튼이 보인다. |
| 월드맵 | 최소 1개 스테이지와 잠김/진입 상태가 보인다. |
| 던전 시야 | 1인칭 던전 크롤러 느낌과 좌우 회전 또는 방 이동 감각이 있다. |
| 전투 | 몬스터, 손패 5장, 에너지, HP, 적 의도, 카드 사용 결과가 보인다. |
| 보상 | 선택지, 추천 이유, 획득 결과가 보인다. |
| 룬/보석 장착 | 카드 슬롯, 장착 후보, 장착 전후 효과 변화가 보인다. |
| 보스전 | 보스 실루엣, 페이즈 또는 특수 의도, 보상 연결이 보인다. |
| 결과/복귀 | 해금 또는 진행 상태 변화와 마을 복귀가 보인다. |

## 데이터 통과 기준

- 모든 표시 텍스트는 한글 데이터 또는 locale 계층에서 온다.
- 모든 주요 콘텐츠는 `id`, `displayNameKo`, `descriptionKo`, `referenceRole`, `evidence`를 가진다.
- 데이터가 참조하는 에셋 키는 매니페스트에 존재한다.
- 손패 5장, 몬스터, 보스, 보상, 룬/보석은 하드코딩된 화면 장식이 아니라 데이터에서 로드된다.
- 원작 대응이 불명확한 수치는 `draft` 또는 후보 범위로 표시한다.

## 아트 통과 기준

- 화면 전체가 `프리미엄 팝업북 판타지 카드 크롤러`로 읽힌다.
- 카드, UI, 배경, 몬스터가 같은 종이극장 재질 언어를 공유한다.
- 카드 텍스트와 버튼 텍스트가 질감에 묻히지 않는다.
- 몬스터와 보스는 종이 질감이어도 약해 보이지 않는다.
- 통짜 화면 이미지를 붙인 것이 아니라 조립 가능한 에셋 구조를 사용한다.
- 첫 샘플은 카드, 몬스터, 배경, 이펙트가 같은 화면에서 어울려야 한다.

## 전투 통과 기준

- 플레이어는 이번 턴에 어떤 카드를 낼지 판단할 수 있다.
- 카드 비용, 사용 가능/불가능 상태, 주요 효과가 보인다.
- 적 의도와 다음 위험이 보인다.
- 카드 사용 후 피해, 보호막, 드로우, 상태 변화 중 실제 발생한 결과가 피드백된다.
- 카드 사용 애니메이션, 피격, 피해 숫자, 짧은 이펙트가 최소 1회 이상 동작한다.
- 전투 로그 또는 디버그 로그로 실제 처리 결과를 확인할 수 있다.

## 던전 통과 기준

- 던전은 단순 메뉴 이동이 아니라 방 이동 또는 회전 감각을 가진다.
- 현재 방, 다음 방 후보, 보스까지의 진행감이 보인다.
- 전투 방과 보상 방이 같은 진행 흐름 안에서 이어진다.
- 보스전 진입이 별도 장식이 아니라 진행 구조의 결과로 발생한다.

## 저장과 해금 통과 기준

- 최소 저장 데이터는 `saveVersion`, 프로필, 현재 런 또는 최근 결과, 설정을 구분한다.
- 해금 또는 진행 상태 변화가 마을 복귀 후 보인다.
- 저장에는 Phaser 오브젝트가 들어가지 않는다.
- 디버그 초기화가 가능해야 한다.

## 디버그 통과 기준

아래 기능은 개발 초기에 반드시 필요하다.

- 특정 스테이지 진입
- 특정 전투 진입
- 특정 보스전 진입
- 카드 지급
- 룬/보석 지급
- 보상 풀 테스트
- 세이브 초기화
- 전투 로그 보기
- 애니메이션 프레임 보기

디버그 UI는 최종 아트풍을 따르지 않아도 되지만, 기능은 명확해야 한다.

## 반응형 기준

- 기준 화면: `1920x1080`
- 최소 검증: `1280x720`
- 1920 기준에서 카드 5장과 전투 정보가 한 화면에 안정적으로 들어와야 한다.
- 1280 기준에서 핵심 텍스트가 잘리거나 겹치면 통과하지 않는다.
- 모바일은 1차 최적화 대상이 아니지만, 화면이 완전히 깨지는 상태는 남기지 않는다.

## 검증 방법

첫 세로 조각은 아래 검증을 통과해야 한다.

| 검증 | 방법 |
| --- | --- |
| 데이터 참조 | 데이터 검증 스크립트로 누락 ID, 빈 한글 문구, 없는 에셋 키 확인 |
| 원작 대응 | `referenceRole` 누락과 evidence 상태 확인 |
| 브라우저 실행 | 로컬 Vite/Phaser 실행 후 콘솔 오류 확인 |
| 화면 검수 | 1920x1080, 1280x720 스크린샷 확인 |
| 전투 동작 | 카드 사용, 적 행동, 보상, 장착, 보스전, 복귀를 수동 또는 자동 smoke로 확인 |
| 저장 | 새로고침 또는 재진입 후 해금/진행 상태 확인 |

## 통과 불가 조건

아래 중 하나라도 있으면 세로 조각 통과로 보지 않는다.

- 통짜 이미지만 있고 실제 데이터/상호작용이 없다.
- Phaser 씬이 아니라 정적 HTML 목업만 있다.
- 카드나 몬스터가 원작 이름, 문구, 그래픽을 직접 복제한다.
- 카드 5장 손패 판단이 없다.
- 보상 선택이 다음 상태로 이어지지 않는다.
- 룬/보석 장착이 실제 카드 효과에 반영되지 않는다.
- 보스전이 일반 몬스터 수치 변경에 불과하다.
- 한글 텍스트가 잘리거나 버튼 밖으로 밀린다.
- 디버그 진입 도구가 없다.
- 검증 없이 완료라고 말한다.
