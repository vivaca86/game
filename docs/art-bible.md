# 아트 바이블 v1

작성일: 2026-05-26

## 상태

- 상태: 핵심 방향 확정
- 기준 엔진: `Phaser 3 + TypeScript + Vite`
- 기준 그래픽풍: `프리미엄 팝업북 판타지 카드 크롤러`
- 기준 에셋 규격: `docs/asset-production-spec.md`
- 남은 작업: 색상 코드, 타입별 UI 상세, 몬스터 계열표, 첫 샘플 에셋 검증

## 한 줄 방향

밝지만 기묘한 고급 종이극장 판타지 안에서, 카드와 룬과 유물이 팝업북 무대 장치처럼 펼쳐지는 2D 카드 던전 크롤러.

## 핵심 키워드

- 프리미엄
- 팝업북
- 종이극장
- 밝지만 기묘함
- 카드 크롤러
- 손맛 있는 전투
- 한글 가독성
- 레이어드 무대
- 종이 질감
- 강한 실루엣

## 타깃 감정

플레이어는 화면을 보고 아래 감정을 받아야 한다.

- 밝다.
- 신비롭다.
- 게임답다.
- 수집하고 싶다.
- 카드가 강해 보인다.
- 보스가 위협적이다.
- 선택지가 읽힌다.
- 전투가 가볍지 않다.

## 전체 톤

확정 방향:

- 밝지만 기묘한 고급 종이극장 판타지

적용 기준:

- 화면 전체는 밝고 오래 봐도 피로하지 않아야 한다.
- 일반 화면은 따뜻하고 초대하는 느낌을 유지한다.
- 몬스터, 보스, 이벤트, 특수 보상에는 살짝 불안하고 신비한 감정을 섞는다.
- 너무 안전한 동화풍이나 너무 어두운 던전풍으로 가지 않는다.

## 색상 팔레트

확정 방향:

- 아이보리
- 잉크블루
- 코랄
- 금색

역할:

- 아이보리: 종이, 카드 본문, 기본 UI 배경
- 잉크블루: 그림자, 외곽선, 깊이, 밤/기묘함
- 코랄: 공격, 경고, 피격, 긴장감
- 금색: 유물, 희귀도, 보상, 프리미엄 장식

보조색:

- 민트/청록: 룬, 마법, 연결, 흐름
- 잎색/연두: 회복, 안정, 자연 계열
- 라벤더: 상태이상, 저주, 기묘한 이벤트

금지:

- 지나친 파스텔 일색
- 전체가 보라/파랑/금색 한 계열로만 보이는 팔레트
- 어두운 검정 배경 중심
- 카드 본문 대비를 해치는 텍스처

## 선 스타일

확정 방향:

- 중간 굵기의 잉크 라인

적용 기준:

- 외곽선은 너무 얇지 않게 유지한다.
- 축소된 카드/아이콘에서도 실루엣이 읽혀야 한다.
- 검정 선 대신 잉크블루, 짙은 남색, 짙은 갈색을 우선한다.
- 코믹북처럼 과하게 두꺼운 선은 특수 이펙트나 강조 컷에만 제한한다.

## 종이 질감 강도

확정 방향:

- 중간 강도

적용 기준:

- 캐릭터, 몬스터, 배경, UI 모두 종이극장 느낌을 공유한다.
- 종이 질감이 텍스트와 실루엣을 방해하면 안 된다.
- 카드와 UI는 종이 질감을 가지되 플레이 UI로 읽혀야 한다.
- 보스와 공격 이펙트는 종이 질감 위에 강한 형태와 대비를 추가한다.

## 형태 언어

기본 형태:

- 두꺼운 종이 단면
- 접힌 모서리
- 컷아웃 실루엣
- 레이어드 무대
- 황동 고정핀
- 리본과 실
- 스티커형 장식
- 펼쳐지는 페이지 구조

사용 기준:

- 둥근 사각형 UI만 반복하지 않는다.
- 장식은 기능을 설명해야 한다.
- 컷아웃 형태는 실루엣 판독에 도움이 되어야 한다.
- 종이 단면과 접힘 그림자로 깊이감을 만든다.

## 재질 언어

주요 재질:

- 두꺼운 종이
- 양피지
- 유리종이
- 스티커
- 황동 핀
- 잉크
- 실/리본
- 무대 조명
- 접힌 그림자

적용 기준:

- 룬/보석은 유리종이 토큰과 스티커 사이의 느낌을 사용한다.
- 유물은 종이 무대 소품처럼 보이되 보상 가치가 느껴져야 한다.
- 아르카나는 팝업북 장면 카드 또는 운명 페이지처럼 보인다.
- UI 패널은 종이와 황동 핀, 리본으로 조립된 느낌을 준다.

## 조명 규칙

- 전체 조명은 밝다.
- 카드 영역은 항상 읽히는 중립 조명을 가진다.
- 전투 중심부는 배경보다 대비가 강해야 한다.
- 보스 등장 시 무대 스포트라이트 느낌을 사용한다.
- 피격, 공격, 보상 획득 순간에는 조명 섬광을 짧게 사용한다.
- 배경 조명이 카드 텍스트보다 튀면 안 된다.

## 카메라와 구도

- 1인칭 던전 크롤러 시야를 유지한다.
- 중앙에는 몬스터 또는 보스의 실루엣 공간을 확보한다.
- 하단 카드 5장 영역은 항상 고정 기준으로 둔다.
- 좌우 HUD는 전투 시야를 가리지 않는다.
- 배경은 후경, 중경, 전경, 바닥, 소품 레이어로 깊이를 만든다.
- 좌우 회전 시 레이어가 바뀌는 느낌을 줄 수 있어야 한다.

## 카드 디자인 규칙

확정 방향:

- 일반 카드는 팝업북 페이지 카드
- 특수 카드, 아르카나, 이벤트 카드는 무대 티켓 또는 장면 카드 요소를 일부 사용

필수 요소:

- 비용 영역
- 제목 영역
- 일러스트 영역
- 효과 텍스트 영역
- 타입 표시
- 룬/보석 슬롯
- 강화/진화 표시

규칙:

- 카드 프레임은 화려함보다 가독성을 우선한다.
- 카드 타입은 색과 아이콘으로 동시에 구분한다.
- 한글 효과 텍스트 2-3줄이 안정적으로 들어가야 한다.
- 손패, 보상, 도감, 미리보기 크기에서 모두 읽혀야 한다.

## UI 디자인 규칙

확정 방향:

- 종이 + 황동 핀 + 리본

적용 기준:

- 패널은 9-slice 구조로 만든다.
- 버튼은 normal, hover, pressed, disabled 상태를 가진다.
- 보상창은 종이 무대가 펼쳐지는 느낌을 준다.
- 마을/월드맵 UI는 책장 또는 무대 장치처럼 열리는 구조를 사용할 수 있다.
- 디버그 UI는 개발용이므로 장식보다 정보 밀도와 명확성을 우선한다.
- 한글 긴 문장이 버튼 밖으로 밀리지 않아야 한다.

## 몬스터 방향

확정 방향:

- 일반 몬스터: 기묘한 동화 속 괴물
- 엘리트/보스: 무대 장치형 몬스터

규칙:

- 몬스터가 모두 같은 종이 인형처럼 보이면 안 된다.
- 각 계열은 실루엣, 색, 재질, 공격 이펙트가 달라야 한다.
- 종이 질감이어도 약해 보이면 안 된다.
- 공격과 피격 프레임에서 형태 변화가 보여야 한다.

초기 계열 후보:

- 접힌 기사 계열
- 잉크 그림자 계열
- 스티커 괴수 계열
- 무대 소품 골렘 계열
- 책갈피 마수 계열
- 실타래/리본 계열

## 보스 방향

확정 방향:

- 거대한 팝업 무대 장치 + 찢어진 이야기의 주인공

규칙:

- 보스는 일반 몬스터보다 화면 장악력이 커야 한다.
- 페이즈 변화는 무대 장치가 바뀌는 느낌으로 표현한다.
- 보스의 약점, 다음 행동, 페이즈 임박 상태가 시각적으로 읽혀야 한다.
- 보스는 예쁘기만 하면 안 되고 전투 허들처럼 느껴져야 한다.

## 배경 규칙

확정 방향:

- 3-5 레이어 종이 무대

기본 레이어:

- 후경
- 중경
- 전경
- 바닥
- 소품

규칙:

- 평면 그림 한 장처럼 보이면 안 된다.
- 길, 문, 방 전환 방향이 읽혀야 한다.
- 몬스터 뒤 공간을 비워 전투 대상이 묻히지 않게 한다.
- 카드 영역과 배경이 시각적으로 충돌하지 않게 한다.

## 이펙트 규칙

역할별 언어:

- 물리 공격: 종이 찢김, 접힘 베기
- 마법 공격: 잉크 번짐, 붓자국, 룬 발광
- 피격: 스티커 파편, 종이 접힘 충격, 짧은 조명 섬광
- 회복: 종이 꽃, 접힌 잎, 따뜻한 빛
- 강화/보상: 무대 조명, 금박 파편, 스티커 반짝임

금지:

- 실사 불꽃/먼지 파티클 남발
- 종이풍과 맞지 않는 금속성 폭발
- 수치 없는 장식 이펙트만 단독 사용

## 애니메이션 톤

- 종이가 접히고 튀는 느낌을 사용한다.
- 카드가 무대 소품처럼 펼쳐지고 닫힌다.
- 공격은 빠르고 날카롭게 찢기거나 접힌다.
- 피격은 실루엣이 접히거나 흔들린다.
- 보스 페이즈는 무대 세트가 갈아끼워지는 느낌을 준다.
- 애니메이션은 화려함보다 판독성과 타격 타이밍을 우선한다.

## 마을과 허브

확정 방향:

- 이야기책 서재 + 종이극장 무대 뒤편

적용 기준:

- 마을은 시스템 허브로 읽혀야 한다.
- 상점, 대장간, 룬/보석, 유물, 아르카나는 각각 무대 장치나 책장 섹션처럼 분리한다.
- 기능이 많아도 메뉴가 장식에 묻히지 않아야 한다.
- 장기 해금과 수집 목표가 시각적으로 보여야 한다.

## 제작 파이프라인

기본 흐름:

1. 시안 또는 원화 생성
2. 스타일 기준 검수
3. 필요한 경우 보정
4. 투명화 또는 레이어 분리
5. 크기 정규화
6. 앵커 확인
7. 파일명 규칙 적용
8. 메타데이터 작성
9. atlas 패킹
10. Phaser 적용
11. 스크린샷 검수

AI 생성 이미지는 최종 게임 화면을 통째로 대체하지 않는다. 생성 이미지는 원화, 일러스트, 스프라이트 원본, 아이콘 초안으로 사용한다.

## 검수 기준

- 1920x1080 기준에서 카드 5장이 읽혀야 한다.
- 1280x720 축소에서도 핵심 카드 정보가 잘려서는 안 된다.
- 회색조로 봐도 카드 타입, 몬스터 계열, 보스가 구분되어야 한다.
- 한글 효과 텍스트가 장식에 묻히지 않아야 한다.
- 몬스터와 보스 실루엣이 중앙에서 즉시 읽혀야 한다.
- 공격 순간에 타격 방향과 대상이 읽혀야 한다.
- 카드, 룬/보석, 유물, 아르카나가 서로 다른 물건으로 보여야 한다.
- 같은 계열 에셋은 일관되되, 전부 같은 실루엣이면 안 된다.

## 금지 스타일

- 유아틱한 그림책
- 싸구려 모바일 UI
- 흐릿한 생성형 판타지
- 지나친 파스텔
- 너무 어두운 던전
- 과한 장식으로 한글이 안 읽히는 카드
- 카드/룬/유물이 서로 구분되지 않는 디자인
- 몬스터가 모두 같은 종이 인형처럼 보이는 디자인
- 통짜 이미지 UI

## 위험 요소와 방지책

| 위험 | 방지책 |
| --- | --- |
| 팝업북이 유아틱해짐 | 프리미엄 종이극장, 중간 굵기 잉크 라인, 강한 몬스터 실루엣 유지 |
| 전투 타격감 약화 | 찢김, 잉크 번짐, 접힘 폭발, 조명 섬광, 피격 실루엣 변화 사용 |
| UI가 컨셉아트처럼만 보임 | 텍스트 엔진 렌더링, 9-slice, 버튼 상태, 한글 여백 기준 고정 |
| 에셋 일관성 흔들림 | 공통 프롬프트, 팔레트, 선 굵기, 메타데이터, 정규화 과정 사용 |

| 배경 평면화 | 3-5 레이어 종이 무대와 1인칭 길 구조 유지 |
| 한글 가독성 저하 | 카드 본문 대비 우선, 장식 제한, 2-3줄 효과 텍스트 검수 |
| 제작량 폭발 | 계열 베이스 재사용, 보스만 완전 고유 제작, 카드 타입별 모듈 사용 |
| Phaser 구현 부담 | 스프라이트/트윈/atlas/9-slice 중심, 복잡한 쉐이더와 실시간 물리 지양 |
